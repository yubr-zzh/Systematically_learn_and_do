# 定位与目标：
一个网页端工具，主要用于辅助用户的学习(learn)和日常项目/计划(do)。而且，这个工具会聚焦于系统性与结构性，旨在：
一、能够帮助用户有系统、有计划地去学习某个领域的某个方面的知识；
二、对于用户即将要做的项目/计划，结合已有的一些实践/他人经历，帮用户草拟一份计划与进度表。

---

# 实现细节：
这个工具，现阶段会结合三个 skill 来做（均位于 `skills/` 目录下）：
- **horizontal-vertical-analysis.md**（横纵分析法，由卡兹克提出）：先纵向（时间线）再横向（当下多赛道），然后两条轴交叉起来，从而快速入门、上手一个新概念/领域。
- **deep-research-workflow.md**（深度调研 Workflow）：结合用户的一些规划/计划，去网上搜一下相关实践，并从中吸取一些精华范式、常见坑点，沉淀下来。
- **plan.md**（规划 Skill）：在深度调研的基础上，将调研结果转换为对用户的建议、生成一份规划（规划中应包含实现路线，避免踩坑的地方以及一些锦囊妙计以防用户在某个方面或阶段卡住）。

## 各功能页设计

### 1. Learn（学习模式）
- **输入区**：用户输入想学习的主题（如"React 框架"）
- **三阶段进度条**：
  - 阶段1: 横纵分析（进行中）
  - 阶段2: 深度调研（待完成）
  - 阶段3: 规划建议（待完成）
- **报告展示区**：markdown 渲染的报告内容，支持分段展开/收起
- **交互功能**：收藏、导出、分享、历史记录

### 2. Project（项目模式）
- **项目列表**：卡片式展示，显示项目名称、状态、进度
- **新建项目**：表单输入项目描述、目标、时间预期
- **报告展示**：类似 Learn 的报告格式，但侧重于实施路线图
- **任务追踪**：可选的 TODO 列表功能

### 3. Feedback（反馈）
- **报告评价**：用户对生成的报告打分、评论
- **建议提交**：可以提出改进建议
- **历史反馈**：查看之前的反馈记录

### 4. Settings（设置）
- **用户配置**：主题偏好、字体大小
- **数据管理**：导出数据、清除历史
- **Skill 管理**：查看/编辑/归档 skill，查看进化日志

# 数据存储

## 存储方案：分层 JSON 文件系统

所有数据存储在 `data/` 目录下，结构清晰，易于回溯。

```
data/
├── config/                    # 用户配置
│   ├── user.json              # 用户基本信息、偏好设置
│   └── settings.json          # 应用全局设置
│
├── learn/                     # 学习报告
│   ├── [project-name]/        # 每个学习项目一个文件夹
│   │   ├── metadata.json      # 元数据：标题、创建时间、状态
│   │   ├── report.md          # 完整的 markdown 报告
│   │   └── history/           # 版本历史
│   │       ├── v1_2024-01-01.md
│   │       └── v2_2024-01-05.md
│   └── index.json             # 学习列表索引
│
├── projects/                  # 项目规划
│   ├── [project-name]/
│   │   ├── metadata.json
│   │   ├── report.md
│   │   ├── tasks.json         # 任务列表
│   │   └── history/
│   └── index.json
│
├── feedback/                  # 用户反馈
│   ├── [report-id]/
│   │   ├── feedback.json
│   │   └── ratings.json
│   └── index.json
│
├── skills/                    # Skill 库（用户创建的模板）
│   ├── react-ecosystem.md
│   ├── microservices.md
│   └── index.json
│
└── archives/                  # 归档（已不活跃的项目/学习/skill）
    └── ...
```

## 数据层说明

| 层级 | 说明 |
|------|------|
| **用户层** | `config/user.json` - 用户名、头像、主题偏好 |
| **配置层** | `config/settings.json` - 全局设置、skill 参数 |
| **项目层** | 每个学习/项目独立文件夹，包含 metadata + report |
| **历史层** | 每个报告有多个版本，便于回溯 |
| **索引层** | `index.json` 文件提供快速列表查询 |
| **Skill 层** | `skills/` 存储用户积累的调研模板 |

## 关键设计原则
1. **分层清晰**：每个报告独立文件夹，互不干扰
2. **元数据分离**：metadata.json 与报告内容分开，便于程序读取
3. **版本回溯**：history/ 目录保存所有历史版本
4. **易于备份**：整个 data/ 目录可打包迁移

# 自进化方式

借鉴 Hermes Agent 的自进化理念，结合 Web 端学习/规划工具的特性，设计以下自进化机制：

## 核心思路

Hermes Agent 的自进化核心是**"从经验中创建 skill，持续自我改进"**。我们的工具将这一理念转化为：**从调研经验中积累模板，从用户反馈中优化方法**。

```
用户输入主题 → 检索相关 skill → 执行调研 → 生成报告
                                              ↓
用户反馈（评分/评论/编辑）←←←←←←←←←←←←←←←←←←←←←←←←←
        ↓                                    ↑
   更新 skill / 创建新 skill ←←←←←←←←←←←←←←←←←←←
        ↓
   Curator 生命周期管理
```

---

## 一、Skill 自主创建（经验沉淀）

### 触发条件
| 触发场景 | 动作 |
|----------|------|
| 完成复杂调研任务（3 阶段全部完成） | 自动将本次调研方法封装为可复用 skill |
| 用户点击「保存为模板」 | 手动触发 skill 创建，允许用户自定义名称和适用范围 |
| 同一主题多次调研结果高度相似 | 自动合并为通用模板 |

### Skill 内容结构
```yaml
---
name: [模板名称]
description: [适用场景描述]
version: 1.0.0
created_from: [原始调研主题]
use_count: 0
rating: 0
---

# [模板名称]

## 适用范围
- [适用场景 1]
- [适用场景 2]

## 核心维度
[根据历史调研提炼的关键分析维度]

## 注意事项
[本次调研中发现的重要要点]
```

### 示例：`react-ecosystem.md`
```yaml
---
name: react-ecosystem
description: React 生态系统的横纵分析法模板
version: 1.0.0
created_from: React 框架
use_count: 5
rating: 4.5
---

# React 生态系统调研模板

## 纵向分析重点
- React 版本演进（0.8 → 16 → 17 → 18 → Fiber）
- 关键架构决策（Class → Hooks → Server Components）
- 社区生态发展（React Router, Redux, Next.js 等）

## 横向分析竞品
- Vue.js、Svelte、Solid.js
- 对比维度：性能、学习曲线、生态完整性、TypeScript 支持

## 常见坑点
- Hooks 依赖数组管理陷阱
- Context 性能问题
- SSR/SSG 选型困惑
```

## 二、Skill 自我改进（反馈驱动）

### 改进触发条件
| 触发条件 | 改进动作 |
|----------|----------|
| 用户对报告评分 ≤ 3 星 | 标记 skill 需要补充的维度，触发重新调研 |
| 用户评论指出缺失内容 | 自动更新 skill 的对应章节 |
| 同一 skill 被使用 10+ 次且评分稳定 | 生成 v2 版本，尝试优化 prompt |
| 用户手动编辑报告内容 | 提取修改意见，应用到 skill 模板 |

### 改进机制
```
用户反馈 → 分析问题 → 定位 skill 不足 → 生成改进建议 → 用户确认 → 更新 skill
```

### 版本管理
- 每次改进生成新版本（v1 → v1.1 → v2）
- 保留历史版本，可随时回退
- 被标记为 "stale" 的 skill 提示用户是否需要更新

---

## 三、Curator 生命周期管理

借鉴 Hermes 的 Curator 机制，管理 skill 库的完整生命周期：

| 状态 | 定义 | 处理方式 |
|------|------|----------|
| **活跃** | 近 30 天内有使用 | 正常参与调研 |
| **观察** | 30-90 天未使用 | 标记提醒，但不删除 |
| **stale** | 90 天以上未使用 | 建议归档或更新 |
| **归档** | 超过 180 天未使用 | 移入 archives，保留备份 |
| **pinned** | 用户手动固定 | 不受自动归档影响 |

### 配置参数
```json
{
  "curator": {
    "enabled": true,
    "check_interval_hours": 24,
    "active_threshold_days": 30,
    "watch_threshold_days": 90,
    "stale_threshold_days": 180,
    "archive_after_days": 365
  }
}
```

### UI 展示
在 Settings 页面增加 **Skill 管理** 模块：
- 显示所有 skill 列表及使用统计
- 筛选：全部 / 活跃 / 观察 / stale / 归档
- 操作：查看详情、编辑、pinned、手动归档、查看进化日志

## 四、Guardrails（安全保障）

确保自进化过程安全可控：

| 保障机制 | 说明 |
|----------|------|
| **大小限制** | Skill 文件 ≤ 10KB，避免过度膨胀 |
| **语义保持** | 改进后的 skill 不能偏离原始目的（通过关键词检测） |
| **人工审核** | 重大变更需用户确认，小优化可自动应用 |
| **版本回退** | 任何 skill 都可回退到历史版本 |
| **备份机制** | 每次更新前自动备份当前版本 |

## 五、与 Web 端的结合点

### 1. 数据流
```
用户输入主题
    ↓
检索相关 skill（优先使用已有模板）
    ↓
执行调研 → 生成报告
    ↓
用户反馈（评分/评论/编辑）
    ↓
更新 skill 或创建新 skill
    ↓
Curator 定期维护
```

### 2. 用户可见的进化痕迹
- **智能推荐**：输入主题时，提示"基于历史调研，你可能需要关注..."
- **Skill 标签**：报告页面显示使用的 skill 版本
- **进化日志**：Settings 中可查看 skill 的变更历史

### 3. 个性化积累
- 记录用户的调研偏好（如偏好的深度、关注的维度）
- 随使用时间增长，报告越来越贴合用户个人风格

## 六、与 Hermes Agent 的差异

| 维度 | Hermes Agent | 本工具 |
|------|--------------|--------|
| **Skill 类型** | 代码/工具执行逻辑 | Prompt/调研模板 |
| **进化目标** | 提升任务执行效率 | 提升调研质量和相关性 |
| **反馈来源** | 任务成功/失败 | 用户评分/评论/编辑 |
| **执行环境** | CLI / 本地 | Web 端 / 云端 |
| **安全机制** | 测试套件 | 人工审核 + 版本回退 |
