# Deep Research Workflow

深度调研工作流，整合横纵分析法、深度调研、规划建议三阶段，适用于 Web 端学习和项目规划。

## 适用场景

- **系统学习**: 想系统掌握某个领域的知识
- **项目规划**: 想开始一个新项目，需要调研和计划
- **技能入门**: 想快速入门一个新领域/概念

## 工作流架构

```
用户输入 → [阶段1: 横纵分析] → [阶段2: 深度调研] → [阶段3: 规划建议] → 输出报告
```

## 触发方式

Web 端通过自然语言触发，例如：
- "我想系统学习 React"
- "我想做一个 AI 聊天机器人项目"
- "帮我调研一下微服务架构"

## 阶段说明

### 阶段 1: 横纵分析 (Horizontal-Vertical Analysis)

使用 `horizontal-vertical-analysis` skill（基于卡兹克的横纵分析法）：

**纵向分析**：
- 起源追溯：诞生的背景、技术/理念/需求
- 诞生节点：首次发布/成立时间，最初形态
- 演进历程：按时间顺序梳理关键节点
- 决策逻辑：还原决策背后的原因

**横向分析**：
- 竞品对比：核心差异、用户视角、生态位
- 趋势判断：在竞争格局中的走向

**输出**: 结构化的分析框架，定义后续调研的范围和维度。

### 阶段 2: 深度调研 (Deep Research)

基于阶段1的分析框架：
- 搜索相关实践/案例
- 提取关键模式 (patterns)
- 识别常见陷阱 (common pitfalls)
- 整理最佳实践

使用 `grounded-citations` skill 管理引用。

### 阶段 3: 规划建议 (Planning)

基于阶段1+2的结果：
- 生成实施路线图
- 标注需要避开的坑
- 提供各阶段的"小贴士"
- 给出可执行的时间表

使用 `plan` skill 生成结构化计划。

## 使用方法

### 1. 接收用户输入

用户通过 Web 端输入主题，例如：
- 学习目标: "我想学 AI 大模型"
- 项目目标: "我想做一个知识库系统"

### 2. 执行阶段 1: 横纵分析

将用户的 [主题] 填入横纵分析法 prompt：

```
# 横纵分析法 Deep Research Prompt

## 变量定义
- 研究对象 = 「[用户主题]」

[使用水平-垂直分析skill的内容...]
```

### 3. 执行阶段 2: 深度调研

根据阶段1的分析框架，进行深度调研：
```
对 [分析框架中的各维度] 进行深度调研
搜索相关实践案例、提取关键模式、识别常见陷阱
```

### 4. 执行阶段 3: 规划建议

基于调研结果，生成计划：
```
基于以上分析和调研，生成学习/项目计划
包含：实施路线、避坑指南、各阶段目标
```

### 5. 输出最终报告

整合三个阶段的输出，生成完整的报告，格式：

```markdown
# [主题] 深度调研报告

## 一、横纵分析

### 1.1 纵向发展历程
[时间线内容]

### 1.2 横向现状对比
[各方向/赛道对比]

### 1.3 交叉定位
[推荐切入点]

## 二、深度调研

### 2.1 关键模式
[提取的模式]

### 2.2 常见陷阱
[需要避免的问题]

### 2.3 最佳实践
[推荐的做法]

## 三、规划建议

### 3.1 实施路线
[阶段式路线图]

### 3.2 避坑指南
[各阶段可能的问题]

### 3.3 时间规划
[建议的时间分配]
```

## 输出格式要求

1. **结构化**: 使用 markdown 标题层级
2. **可操作**: 计划部分要具体可执行
3. **有引用**: 调研部分使用 `grounded-citations` 标注来源
4. **适度的长度**: 完整但不过于冗长

## 自进化机制

当用户反馈某些方面不足时，系统可以：
1. 识别需要增强的 skill 模块
2. 调用对应 skill 进行补充调研
3. 更新现有报告

## 与其他 Skills 的关系

| Skill | 角色 | 调用方式 |
|-------|------|----------|
| `horizontal-vertical-analysis` | 阶段1: 分析框架 | 直接调用（卡兹克版） |
| `grounded-citations` | 阶段2: 引用管理 | 作为工具使用 |
| `plan` | 阶段3: 计划生成 | 复用其格式 |

## Web 端适配

1. **渐进式展示**: 可分阶段展示，每个阶段完成后让用户确认
2. **移动端友好**: 输出考虑移动端阅读体验
3. **用户参与**: 可以在每个阶段后让用户确认方向
4. **迭代深化**: 用户可以针对特定维度要求更深入的调研

## 注意事项

1. **上下文保持**: 三个阶段的输出需要相互引用，保持一致性
2. **引用规范**: 调研部分必须使用 `grounded-citations` 管理来源
3. **计划可执行**: 规划部分要具体，避免空泛的建议
